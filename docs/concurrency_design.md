### Server Concurrency Strategy

- **Architecture Choice:** Multithreading is the architecture of choice for this project's concurrency management. Threads are, in general, more straightforward than non-blocking socket select, with more precise management of behind-the-scenes processes (e.g. updating game state, validating questions, etc.). A thread in Python is a sequence of instructions that the client and server manage. Multithreading allows for the client and server to handle multiple actions simultaneously, while state is maintained between the two. Importantly, Python multithreading allows the various threads to share code, which, for Headbands, is very practical, as there are only two roles either client may be. There is also no way to "block" the server using multithreading, as both threads are separate events and thus do not have to wait for each other unless told specifically to do so.
